# 2.2.2：五项导出保真复查

| 问题 | 原因与处理 | 可验证的边界 |
| --- | --- | --- |
| SVG 图片缺失 | 图片下载入口只接收位图 data URI，误拒绝 data:image/svg+xml；现支持 UTF-8、Base64，清理后写为本地 SVG 资源 | 历史包若 src 和字节均已清空，需从仍有原图的页面重新导出 |
| 术语解释丢失 | 操作行重建只识别按钮，没有关联展开后的正文；现读取展开状态、aria-controls 或紧邻 aside，支持原生与 ARIA 按钮，并写为 toggle 的真实内容 | 未展开且未声明的隐藏业务内容，不执行未知 onClick；不会生成原文不存在的解释 |
| 表单值与类型不符 | 原下拉控件被替换为一个字符串；单选重建取首字段；范围控件依赖旁边的静态文字 | 现保留下拉 options、原控件实时 value/checked、滑块 min/max/step；保留可见参考地址。选项确实缺失时继续使用 2.2.1 的带说明文本回退，不阻断 ZIP |
| 附件链接缺失 | 原流程只打包声明式 file 组件，普通下载 anchor 未纳入 | 现打包已知 href/download/data-href/data-url 的常见文件地址；网络失败保留地址。只有 role=link 和点击回调的入口，DOM 没有可下载字节，需要在原页另存文件 |
| 架构图箭头偏左 | 箭头是独立 SVG icon，之前仅文字箭头执行居中规则 | 竖向布局的直接子 SVG 图标居中；表单恢复紧凑间距、分段文字颜色和滑块样式，浅深主题共享规则 |

这里的处理按结构与数据类型进行，不根据示例标题或项目名称填补数据。AI 不能补回已经没有的原文件字节、真实链接或业务回调；如需 AI 重建，应另行明确标注为重建内容。

验证包括 DOM 提取 → ZIP 往返 → 组件渲染和操作，以及打包扩展的 DOM 测试。当前工具不能直接检查用户登录后的 Chrome 页面，因此不宣称已完成逐页截图视觉验收。


## 2.2.3：本次八项比较

- 任务圈固定 20×20，避免 flex-basis 与高度不一致拉成椭圆。
- 图解工具栏使用下载/放大图标。静态 SVG 的圆角、虚线按计算样式保留；没有源码的 SVG 不能按参考示例重排节点和边。
- 导出前有界滚动，尝试加载回复与轮播；保存完恢复位置，补充 CSS 背景图片识别。已经丢失的整个轮播无法从现有 ZIP 恢复。
- 图表恢复外框，正文移除重建说明和技术支持字样；重建说明保留在功能块报告。工具栏使用真正的 React 按钮控制数据表、ECharts restore 和 SVG 下载。
- 参考页和导入页共用图表、图解与地图的实际渲染组件，避免两套实现偏离。
- 地图自动查询缺失坐标、缓存成功结果；地图标记、地点卡片、底部地点导航、放大按钮统一。不能唯一定位时不猜测地点，提供重试入口。
- 图片查看按钮背景透明；不删除原 SVG 内真实绘制的背景形状。
- 附件图标根据名称与格式说明选择，统一行距与链接排版；没有源地址的附件显示明确缺失状态，不伪装为可下载链接。

实际上传的 2.2.2 包：轮播章节没有图片组节点，地图三个地点均无坐标，四个 file.src 为空；流程图为无 Mermaid 源码的 SVG 快照。这些数据事实与渲染缺陷分别记录，不能通过填入参考页的示例数据冒充原导出内容。
